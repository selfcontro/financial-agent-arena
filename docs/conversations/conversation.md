## 21. Codex · 2026-09-19T08:09:57.914Z

下一个模块是 **本地存储与状态管理**。这个模块决定评审记录能否可靠保存、刷新后恢复，以及 JSON 导入导出是否可追溯。

## 1. 推荐的状态结构

```ts
type AppState = {
  schema_version: 1;
  updated_at: string;

  models: Model[];
  cases: EvaluationCase[];
  answers: ModelAnswer[];
  reviews: ReviewRecord[];

  scoring: {
    weights: ScoringWeights;
    updated_at: string;
  };

  ui?: {
    filters: FilterState;
  };
};
```

其中：

- `models`：所有模型，包括启用和停用模型。
- `cases`：评测题。
- `answers`：模型回答。
- `reviews`：人工评审记录。
- `scoring.weights`：管理员当前设置的评分权重。
- `schema_version`：用于未来数据结构升级。
- `updated_at`：最后一次数据变更时间。

## 2. `localStorage` 保存方式

使用固定键名：

```text
financial-agent-arena:v1
```

保存内容是完整的 `AppState` JSON：

```ts
localStorage.setItem(
  "financial-agent-arena:v1",
  JSON.stringify(appState)
);
```

建议所有写入都经过统一模块：

```text
src/store/storage.ts
```

负责：

- `loadState()`
- `saveState(state)`
- `clearState()`
- `exportState()`
- `importState(json)`
- `validateState(state)`
```

组件不直接调用 `localStorage`，避免不同页面各自保存导致数据不一致。

## 3. 初始化和恢复流程

应用启动时按以下顺序处理：

1. 读取 `financial-agent-arena:v1`。
2. 如果不存在，加载内置模拟数据。
3. 如果存在，解析 JSON。
4. 使用 Zod 校验数据结构。
5. 校验成功，恢复用户数据。
6. 校验失败，保留错误信息并回退到内置数据。
7. 回退时不覆盖原始错误数据，方便排查。

这样可以保证刷新页面后恢复评审结果，同时避免损坏数据导致应用无法启动。

## 4. 评审记录保存规则

评审记录使用以下唯一键：

```text
case_id + model_id
```

保存时：

- 如果不存在，则新增记录。
- 如果已存在，则修改原记录。
- 不允许产生重复评审记录。
- 每次保存自动更新 `reviewed_at` 和顶层 `updated_at`。
- 保存分数、失败标签、评语和评审状态。

例如：

```ts
{
  case_id: "case-001",
  model_id: "wencai",
  scores: {
    numeric_correctness: 8,
    citation_evidence: 7,
    data_timeliness: 10,
    safety_compliance: 9,
    answer_quality: 8
  },
  failure_labels: ["引用无效"],
  comment: "核心数字正确，但引用来源不完整。",
  status: "completed",
  reviewed_at: "2026-09-19T10:00:00.000Z"
}
```

## 5. 模型停用和历史数据

模型删除建议采用“停用”：

```ts
{
  "model_id": "doubao",
  "name": "豆包",
  "enabled": false
}
```

停用后：

- 新题目不再要求该模型提供回答。
- 历史回答仍然保留。
- 历史评审记录仍然保留。
- 汇总报告默认可以选择是否包含停用模型。
- 用户仍可查看历史评审结果。

这样不会因为模型停用导致历史数据丢失。

## 6. JSON 导入策略

2. 解析并校验结构。
3. 显示导入摘要，例如题目数、模型数、回答数、评审数。
4. 用户确认后备份当前状态。
5. 用导入数据整体替换当前状态。
6. 写入 `localStorage`。
7. 刷新页面后验证数据仍然存在。

导入失败时：

- 不修改当前数据。
- 显示具体错误。
- 保留当前评审状态。

```text

```

- 模型来源

- 引用列表
- 引用来源名称
- 引用发布时间
- 回答生成时间
- 可选延迟和成本
- 当前评审状态
- 当前总分
- 编辑评审按钮
- 删除回答按钮

示例：

```text

│ 同花顺问财                   │

└──────────────────────────────┘

## 3. 动态添加模型回答

添加回答时需要选择：

1. 已有模型，或者先创建新模型。
2. 目标题目。
3. 回答内容。
4. 引用信息。
5. 生成时间。
6. 可选延迟和成本。

同一道题、同一个模型只能有一条当前回答：

```text
case_id + model_id
```

如果已经存在回答，界面应提示用户选择：

- 修改原回答
- 取消添加

不能生成重复回答。

## 4. 动态删除回答

删除回答前需要显示确认信息：

```text
确定删除“豆包”对本题的回答吗？
该回答对应的评审记录也会被删除。
```

推荐删除策略：

- 删除回答。
- 同步删除该回答对应的评审记录。
- 不删除模型本身。

## 1. 总分计算

评分维度从：

```ts

```

中读取，只计算 `enabled: true` 的维度。

公式：

```text
维度得分 = score / 10
加权总分 = Σ(维度得分 × weight) × 100
```

例如：

```text

引用与证据：7 / 10 × 20% = 14
数据时效性：10 / 10 × 15% = 15
安全合规：9 / 10 × 20% = 18
回答质量：8 / 10 × 15% = 12

总分 = 83
```

最终总分保留两位小数。

## 45. Codex · 2026-09-19T12:13:55.962Z

**1. 不同筛选条件用 AND，是为了逐步缩小范围。**

例如你想查看：

> 豆包在“已完成”的评审中，哪些回答存在“数字错误”。

对应：

```text
模型是豆包 AND 状态已完成 AND 包含数字错误
```

结果同时满足这三个条件。

如果使用 OR，则会查出：

```text
所有豆包的回答
或所有模型已完成的评审
或所有存在数字错误的回答
```

范围反而扩大，不符合这次查找目的。因此建议不同类别之间默认 AND；没有选择的条件不限制结果。

**2. 多个失败标签用于集中排查一类问题，或查找多个错误同时出现的回答。**

假设有三条评审：

| 回答 | 失败标签 |
|---|---|
| A | 数字错误 |
| B | 引用无效 |
| C | 数字错误、引用无效 |

选择“数字错误”和“引用无效”时：

- **包含任一**：返回 A、B、C。适合“我要检查数字或引用方面存在问题的回答”。
- **包含全部**：只返回 C。适合“我要找既有数字错误、又有引用问题的回答”。

两层逻辑可以组合：

```text

AND 状态已完成
AND（数字错误 OR 引用无效）
```

对于当前项目，**先支持多选标签、默认包含任一就足够**；“包含全部”可以作为可选增强，不是题目硬性要求。

审计历史模块需要解决两个问题：**知道改了什么，以及知道评分对应哪一版回答。** 建议先讨论下面这套设计，确认后再写入规划。

| 操作 | 保存内容 |
|---|---|
| 修改模型配置 | 修改前后配置，排除 API Key 原文 |
| 新增、修改、删除回答 | 回答版本、变更时间、修改前后内容 |

目前只用 `case_id + model_id`，无法区分修改前后的回答，需要补充：

```ts

  case_id: string;
  model_id: string;
  answer_id: string;
  answer_version: number;

};

- 删除回答：标记为已删除，保留回答版本和关联评审，退出当前统计。

15:10  修改回答：v1 → v2

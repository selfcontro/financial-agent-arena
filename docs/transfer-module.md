# 第七模块：JSON 导入导出与多备份管理

## 文件与交互

侧栏“数据与备份”提供当前数据导出、手动备份、JSON 文件导入及历史备份恢复。

导出为可直接导入的 EvaluationDataset JSON，包括全部题目版本、模型、回答版本、引用、人工评审、规则历史和审计事件。API Key 只在服务器内存，不属于文件字段；模型 Base URL 和 Model Name 随模型配置导出。下载单个备份时也导出其完整数据集，可在其他浏览器导入。

导入流程为文件读取 → JSON 解析 → Zod 与关联校验 → 数量预览 → 用户点击确认 → 自动备份原数据 → 完整替换并新增审计。校验或备份失败不替换，保留可重试的预览。不是合并操作，旧数据和旧历史完整保存在替换前备份中。

恢复流程为选择备份 → 查看数据量及 SHA-256 → 点击确认 → 再次校验备份 → 备份当前数据 → 恢复并新增审计。恢复的数据内容可重现，更新时间与新增操作审计不与原文件逐字相同。

备份列表显示时间、原因和唯一 ID，保留多次备份，不自动清除。损坏或摘要不匹配的备份单独显示错误，不允许恢复。读到损坏的当前存储时仍维持只读保护，并提供原始文本下载以便修复，不把模拟回退数据冒充原始数据。

## 持久化与边界

沿用 `financial-agent-arena:v1` 当前数据键和 `financial-agent-arena:backup:v1:` 独立备份键。备份由已有仓库服务计算内容摘要，包含计算版本、原因及数据快照。单个备份 JSON 下载的是数据集，不是内部备份容器，重新导入会创建新的导入事件；下载文件本身不附带备份容器的摘要。

当前数据导出不打包所有本地备份；要保留替换前的历史链，应分别下载相关备份。清理站点存储会删除本地备份。存储空间不足时停止写入并提示，不删除旧备份腾空间。跨标签页保护沿用存储模块，仍不提供服务端协作或账户体系。

## 验证

`npm test`：8 个文件、60 个测试通过；`npm run build` 通过。新增组件测试覆盖非法 JSON 不写入、预览后确认替换、连续备份、指定恢复且生成恢复前备份，以及备份写入失败阻止替换。已有存储测试覆盖内容摘要、损坏备份、版本关系及导入恢复的审计保护。

2026-09-19 浏览器验证：创建手动备份，选择该备份恢复，出现第二份恢复前备份；刷新页面仍有两份备份，题目、模型、回答与评审数量保留。390px 页面未发生横向溢出。导入文件流程由组件测试验证；尚未通过浏览器文件选择器执行文件往返下载上传验收。
